# Contributing

Thanks for your interest in sigmacatch. This project captures real Windows events via the Windows
Event Log API (winevt) and macOS events via Endpoint Security, matches them against SigmaHQ rules,
and outputs structured regression data compatible with the SigmaHQ format.

## Ways to help

Everything below is welcome; say in the pull request what you checked. No claim
on a roadmap is needed.

- **A bug fix with a regression test.** Open a pull request against `main`. When
  Sigma matching is wrong, attach the rule, a sample event, and the
  `regressiondata-check` output before and after.
- **Regression data.** Rule regression data lives in `sigma/regression_data/`;
  contributing it to the SigmaHQ fork is opt-in (see
  [Contrib workflow](#contrib-workflow)).
- **A new collector, output sink or pipeline.** Keep the architectural
  invariants in [Architecture](#architecture); read
  [`docs/dev/architecture.md`](docs/dev/architecture.md) first.
- **Documentation.** `docs/` is one English tree, one topic per page; build it
  with `.venv-docs/bin/zensical build --clean`.
- **A vulnerability.** Report it privately, never in a public issue —
  [SECURITY.md](SECURITY.md).

## Development setup

Prerequisites:

- Rust (stable, edition 2024 — 1.97.1+), `cargo`, `rustfmt`, `clippy`
- For Windows builds from Linux: `cargo xwin build --release --target x86_64-pc-windows-msvc`
- For macOS builds: a macOS host; the Linux cross-linker has no macOS SDK
- `pipx` (linting scripts only: `typos`, `zizmor`)
- `node` + `npx` (markdownlint only)

Required checks before opening a PR:

```bash
cargo fmt --check
cargo clippy --all-targets -- -W warnings
cargo test --locked
cargo clippy --all-targets --no-default-features --features macos -- -W warnings
cargo test --locked -p sigmacatch --no-default-features --features macos
cargo xwin build --release --target x86_64-pc-windows-msvc
```

The Windows cross-build is required after any code change: `.cargo/config.toml` forces
`+crt-static`, and the resulting standalone `.exe` must stay free of a Visual C++ Redistributable
dependency.

The macOS binary cannot be linked from Linux; the arm64 CI job on `macos-latest` builds, lints and
tests it. A full cross-check from Linux needs the Apple SDK (the C dependencies do not
cross-compile without it), so rely on CI rather than a local darwin target check.

## Lint checks

The CI runs the same checks locally via:

```bash
pipx run typos .
pipx run zizmor .
npx --yes markdownlint-cli2 "docs/**/*.md" "*.md"
cargo deny --all-features check advisories sources licenses bans
```

(`markdownlint` runs in CI as the `DavidAnson/markdownlint-cli2-action`; `npx` is the local
equivalent.)

- `typos` — spelling, configured in `.typos.toml`.
- `zizmor` — GitHub Actions security audit. Remote actions are resolved through
  `.github/workflows/actions.lock`: keep readable tags in `uses:` and regenerate the lockfile
  after any change. In-repo actions use GitHub's self-repository form (`uses: $/...`). Never
  introduce a checkout without `persist-credentials: false`.
- `actions.lock` — generated by `gh actions-lock`; never edit it by hand. Install the extension
  once with `gh extension install github/gh-actions-lock`, then run `gh actions-lock` after
  adding a workflow or changing a `uses:`. CI runs `gh actions-lock --verify`.
- `markdownlint` — configured in `.markdownlint-cli2.yaml`. Keep tables and headings clean.
- `cargo deny` — supply-chain gate. `--all-features` is required: it brings `aya` into the graph,
  the only path to `object 0.40`. Without it, the recorded `object 0.39.1` skip in `deny.toml`
  (pinned by `ar_archive_writer` via `psm`) is falsely reported as unnecessary.

## Commit conventions

One commit = one type of change. Never mix code, docs, and refactors in a single commit. Use
conventional commits:

| Emoji | Type | Example |
|-------|------|---------|
| ✨ | feat | `✨ feat: add Winevt collection` |
| 🐛 | fix | `🐛 fix: handle empty event` |
| 📚 | docs | `📚 docs: update architecture` |
| ♻️ | refactor | `♻️ refactor: extract providers` |
| 🧹 | cleanup | `🧹 cleanup: remove dead code` |
| 💄 | style | `💄 style: fix formatting` |
| ⚡ | perf | `⚡ perf: reduce allocations` |
| 🧪 | test | `🧪 test: add integration test` |
| 🔧 | chore | `🔧 chore: update dependencies` |

> **Note:** With the workspace layout, commit messages may use area-based prefixes (`collector:`, `persist:`, `sensor:`, `detection:`, `runner:`, `core:`, `repo:`) instead of the old crate-based prefixes (`sigmacatch-runner:`, `sigmacatch-detection:`, etc.).

Exception: regression data commits generated by the pipeline use
`🧪 test: add regression data for rule {id}`.

## Pull requests

Open pull requests against `main`, one commit per type of change (see
[Commit conventions](#commit-conventions)).

Use the PR template,
[`.github/PULL_REQUEST_TEMPLATE.md`](.github/PULL_REQUEST_TEMPLATE.md) — GitHub
pre-fills it, and its sections must not be deleted:

- `## Overview` — 2-3 sentences: **what** changed and **why** it is needed; no
  implementation details.
- `## What's new` — grouped by crate / module / subsystem, filenames in
  backticks; `### CI / quality` for gates added or lints ratcheted.
- `## Changed files (<N>)` — grouped by category, not an exhaustive list;
  `git diff --stat` has the full list.
- `## Testing` — every check from [Development setup](#development-setup) with
  its result; `cargo fmt` / `clippy` / `test` / `xwin` are required; say what
  was **not** run.
- `## How to build / run` — reproducible commands for what you touched.
- `## Checklist` — tick what you verified.

## Architecture

Architectural invariants are non-negotiable; read them in
[`docs/dev/architecture.md`](docs/dev/architecture.md) before touching the
pipeline. Highlights:

- One continuous run until Ctrl+C: collect + evaluate + generate (30s) + commit + push.
- All aggregation in memory — no intermediate database.
- Windows collection via the Event Log channels, native ETW (`etw`) and the `sigmacatch` kernel driver (`driver`); Linux collection via auditd tail, builtin syslog files, Sysmon-for-Linux and native eBPF probes.
- Git is SSH-only: transport (clone/fetch/push) goes through the system `ssh` binary (exec'd by grit-lib) in the `sigmacatch-repo` crate; object/index/refs operations go through grit-lib. No token, no HTTP.
- No hand-rolled parsers: use `rsigma-parser`, `serde_yaml`, `serde_json`, etc.
- Security first: validate paths, cap sizes, sanitize inputs.

## Contrib workflow

Pushing regression data to the SigmaHQ fork is opt-in (`git.contrib: true` or `--contrib`).
By default the pipeline makes local commits only.
