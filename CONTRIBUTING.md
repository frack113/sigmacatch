# Contributing

Thanks for your interest in sigmacatch. This project captures real Windows events via the Windows
Event Log API (winevt), matches them against SigmaHQ rules, and outputs structured regression data
compatible with the SigmaHQ format.

## Development setup

Prerequisites:

- Rust (stable, 2021 edition), `cargo`, `rustfmt`, `clippy`
- For Windows builds from Linux: `cargo xwin build --release --target x86_64-pc-windows-msvc`
- `pipx` (linting scripts only: `typos`, `zizmor`)
- `node` + `npx` (markdownlint only)

Required checks before opening a PR:

```bash
cargo fmt --check
cargo clippy --all-targets -- -W warnings
cargo test --locked
cargo xwin build --release --target x86_64-pc-windows-msvc
```

The Windows cross-build is required after any code change: `.cargo/config.toml` forces
`+crt-static`, and the resulting standalone `.exe` must stay free of a Visual C++ Redistributable
dependency.

## Lint checks

The CI runs the same checks locally via:

```bash
uvx typos .
uvx zizmor .
npx --yes markdownlint-cli2 "docs/**/*.md" "*.md"
```

- `typos` — spelling, configured in `.typos.toml`. `docs/fr/**` is excluded (French is legitimate).
- `zizmor` — GitHub Actions security audit. All `uses:` are SHA-pinned; never introduce an
  unpinned action or a checkout without `persist-credentials: false`.
- `markdownlint` — configured in `.markdownlint-cli2.yaml`. Keep tables and headings clean.

## Commit conventions

One commit = one type of change. Never mix code, docs, and refactors in a single commit. Use
conventional commits:

| Emoji | Type | Example |
|-------|------|---------|
| ✨ | feat | `✨ feat: add ETW collection` |
| 🐛 | fix | `🐛 fix: handle empty event` |
| 📚 | docs | `📚 docs: update architecture` |
| ♻️ | refactor | `♻️ refactor: extract providers` |
| 🧹 | cleanup | `🧹 cleanup: remove dead code` |
| 💄 | style | `💄 style: fix formatting` |
| ⚡ | perf | `⚡ perf: reduce allocations` |
| 🧪 | test | `🧪 test: add integration test` |
| 🔧 | chore | `🔧 chore: update dependencies` |

Exception: regression data commits generated by the pipeline use
`test: add regression data for rule {id}` without an emoji.

## Pull requests

Use the PR template. Follow its structure: `## Summary` (1-2 sentences), `## Changes` (grouped by
type with emoji and commit hashes), `## Tests` (results of fmt/clippy/test/build — required), and
`## Files` (list of changed files).

## Architecture

Architectural invariants are non-negotiable; read them in [`AGENTS.md`](AGENTS.md) and
[`docs/en/architecture-reference.md`](docs/en/architecture-reference.md) before touching the
pipeline. Highlights:

- One continuous run until Ctrl+C: collect + evaluate + generate (30s) + commit + push.
- All aggregation in memory — no intermediate database.
- Winevt collection only (`EvtQueryW`/`EvtNext`/`EvtRender`) — no ETW, no ferrisetw.
- No external `git` binary: everything goes through grit-lib via `sigmacatch-repo`.
- No hand-rolled parsers: use `rsigma-parser`, `serde_yaml`, `serde_json`, etc.
- Security first: validate paths, cap sizes, sanitize inputs.

## Contrib workflow

Pushing regression data to the SigmaHQ fork is opt-in (`git.contrib: true` or `--contrib`).
By default the pipeline makes local commits only.
